# 陪辦:整併與執行說明

## 2026-11-07 整併:統一為原生版「陪辦」(請先讀這段)

兩組做法已合併,**以 App 內的原生版為主**,功能名稱統一為「陪辦」。原本的 Vue 網頁版稱為「陪辦網頁原型」。決定與理由:

| 項目 | 整併後 | 理由 |
|---|---|---|
| 長輩端介面 | 台北通 App 內的原生 Flutter 頁面(`lib/page/assist/`) | 首頁持續性倒數徽章、即時推播、完整支援 iOS 動態字型 |
| App 入口 | 首頁「不會用嗎?請人陪我辦」與服務頁熱門「陪辦」,**兩者都開原生流程** | 避免同一個 App 出現兩套入口 |
| 安全模型 | 個資由長輩在自己的台北通上**逐項授權**,協助者看不到內容;以登入身分辨識長輩 | 網頁原型原本由協助者輸入長輩完整身分證與帳號,模擬後端以身分證字號辨識長輩,有個資外流與被試探的風險 |
| 後端 | `assist/assist_backend`(Node,16 項安全與流程測試) | Spring 後端請以此安全規則為準 |
| 工作人員工具 | `assist/assist_web` 承辦工作台:陪辦與表單後台整合在同一個平台、同一套設計語言 | 示範時不用在兩個網站之間切換;舊版單檔表單後台保留在 `/admin/legacy/` |

**從網頁原型挑進來的優點**
- 朗讀:原生頁面直接用手機系統語音(`flutter_tts`),只念說明與風險,不念個資。
- 送出後 10 秒內可撤回(網頁原型原設 5 秒,考量長輩反應時間放寬;後端 `POST /api/elder/sessions/:id/undo`)。
- 台北通風格的「陪辦」圖示(`assets/svg/icon_accompany.svg`)用於首頁與服務頁入口。
- Android 修正全部保留:QR 內建辨識模型、debug 版允許 http、掃描提示文字、`tts` 網頁橋接。
- 承辦人表單後台:用詞改為「開放陪辦」,說明改為逐項授權模型,成功綠色與 App 一致。

**保留但目前沒有接上 App 的部分**
- `services/` 裡的陪辦網頁原型(Vue,含越南文、印尼文介面、看護授權、「有錯」點選)。
  App 已不再從服務頁開啟它;仍可用瀏覽器開 `/assist/` 參考或展示。
- 這套 Vue 展示依賴官方示範帳號 `A123456789`;App 的模擬帳號已改為長輩王大明(`A102837499`),
  用 Vue 版雙手機展示時,看護端請改填 `A102837499`。

**接下來可以做(尚未實作)**
- 協助者工作台多語化(沿用 `services/src/assist/i18n.ts` 的越南文、印尼文翻譯)。
- 看護事先授權、有期限且可撤銷(「我的協助者」)。
- 承辦人表單後台發布的表單,直接成為陪辦的申辦項目(題型對應:身分證、電話、地址→逐項授權;單選、下拉→長輩點選)。
- 實名資料沒有的欄位(例如銀行帳號)由長輩輸入,或協助者先填、長輩以「有錯」點選確認。

## 陪辦網頁原型原始說明(整併前)

「陪辦」讓長輩由 1999 客服、家人、里長或看護協助申請,長輩只需在自己的台北通上用易讀、多語的畫面確認。
示範項目:重陽敬老禮金(匯入銀行帳戶)。**示範資料全部為虛構。**

## 執行方式
**App(Flutter)**
```bash
dart run build_runner build
flutter run --dart-define=ASSIST_SERVICE_URL=https://你的網址/assist/
```
- debug 版沒指定 `ASSIST_SERVICE_URL` 時,預設連 `http://10.0.2.2:5173/assist/`(Android 模擬器連到本機)。
- release 版沒指定時為空字串,「陪辦」入口點了不會開啟。

**微服務(Vue)**
```bash
cd services
pnpm install
pnpm dev --host 127.0.0.1 --port 5173
```
新版 pnpm 預設擋掉 `esbuild`、`vue-demi` 的安裝腳本,會回報 `ERR_PNPM_IGNORED_BUILDS`,但 Vite 仍可執行。

## 後端對接
所有後端呼叫集中在 `services/src/assist/api.ts`,檔頭列出每個函式對應的 Spring API 路徑(`/api/assist/...`)。
有兩種模式:
- **記憶體模擬(預設)**:資料只在這個網頁裡,重新整理就重置,不會跨裝置同步。單機即可完整演示。
- **HTTP 模式**:設定 `VITE_ASSIST_API_BASE` 才啟用,兩支手機連同一個後端(輪詢,不用商用推播)。
  - `VITE_ASSIST_API_BASE=auto`:連同一台電腦的 `:8787`,配合 `services/mock-server/server.mjs`。
  - `VITE_ASSIST_API_BASE=https://host/api/assist`:連到真正的 Spring 後端。

`services/mock-server/server.mjs` 是**開發與展示用的模擬後端**(Node,無額外套件,資料只在記憶體),
路徑與回傳格式和上述 API 一致,Spring 完成後可直接替換。它用請求裡的長輩身分證字號比對長輩;
真實後端必須用登入身分比對。展示步驟見 [雙手機展示動線.md](雙手機展示動線.md)。API 草案見 [長輩端畫面規格.md](長輩端畫面規格.md)(實作路徑以 `api.ts` 檔頭為準)。

## 長輩點選「哪裡不對」
長輩按「有錯」後,不用打字:整頁欄位變成可點選的卡片,點出不對的項目(名字、身分證字號、出生日期、銀行、帳號,
或「這不是我要辦的」),送出後協助者**即時**以自己的語言看到(例如印尼文「Nomor rekening bank salah」)。

## 安全設計重點
- QR 只放一次性、短效代碼,不放個資;兌換時後端必須確認掃描者就是目標長輩(`/qr/redeem`)。
- 長輩端永遠只看到遮罩後的身分證字號。
- 看護需長輩事先授權,有期限且可隨時撤銷。
- 朗讀使用系統內建語音;新邀請通知使用 App 既有的 `notify` 橋接。不使用任何商用推播或雲端服務。

## 已知限制與待辦
- 尚未串接 Spring 後端;客服端後台未在本倉庫。
- 通知目前只在「陪辦」頁面開啟時才會輪詢(每 3 秒);App 在別的頁面或背景時,需要 Flutter 端另外輪詢並有真實後端。
- 兩支手機同步目前只用模擬後端驗證過(瀏覽器 + Android 模擬器);尚未在兩支實機上驗證。
- 越南文、印尼文介面文字為預先翻譯,**請母語者校對**。
- 朗讀的實際聲音、越南文與印尼文語音資料是否安裝,需在實機確認。
- 注音、裝置端 AI 白話化、地圖整合、銀行分行選單(資料集:政府資料開放平臺「總分支機構位置一覽表」24323)尚未實作。
- `services/` 內 `vue-tsc` 在部分環境(Node 22 + 舊版 volar)無法執行;已用 ESLint、`tsc`(僅 `.ts`)與 `vite build` 檢查。
