# 長輩端畫面規格(長者補助 · 協助辦理)

> 範圍:只做「長輩端」。客服後台與 Spring 後端由其他隊員負責,本文件包含給後端的介面需求。
> 欄位與文案為示意,請依真實「長者補助」申請書調整,不要自行編造補助金額或資格。

## 1. 角色
| 代碼 | 協助者 | 說明 |
|---|---|---|
| CS_1999 | 1999 客服 | 電話中協助,代填 |
| FAMILY | 子女/家屬 | 用自己的台北通按「協助辦理」,產生 QR |
| VILLAGE_CHIEF | 里長/里辦公處 | 同上 |
| CAREGIVER | 看護 | 同上,**需長輩事先授權**;看護自己的介面語言可與長輩不同(看護常是外籍) |

## 2. 畫面清單與流程

```
(推播/通知匣)──┐
                ├─> S1 有人要幫你辦 ──同意──> S2 確認資料 ──> S3 最後確認 ──> S4 完成
(掃 QR)────────┘           └─拒絕──> S1-拒絕完成
管理:S5 我的協助者(授權/結束授權)
```

### S1 有人要幫你辦(來電通知或 QR 進入)
- 大標題:「有人要幫你申請『長者補助』」
- 顯示:協助者身分(圖示 + 文字:1999 客服 / 你的兒子 王小明 / 里長 / 看護 Sari)、時間。
- 兩顆大按鈕:「我同意」(綠,打勾圖示)、「不是我要的,拒絕」(灰,叉圖示)。
- 提醒句:「你不同意,他就不能幫你辦。」

### S2 確認資料(最核心)
- **一個欄位一張卡片**,一次顯示一張或一屏 3 張以內。
- 每張卡:圖示 + 欄位白話名稱 + 值。身分證字號遮罩(A12\*\*\*\*789)。
  - 範例:「你的名字 王大明」「你的電話 0912-xxx-xxx」「你住的地方 臺北市…」
- 每張卡右側:🔊 朗讀。
- 頂部固定工具列:語言切換、字體大小(中/大/特大)、注音開關、高對比。
- 底部兩顆按鈕:「都對,下一步」「有錯,請對方改」(送回協助者,附備註)。

### S3 最後確認
- 一句話摘要:「你要申請:長者補助。申請人:王大明。」
- 「確認送出」大按鈕 + 「回上一頁」。
- 送出後 5 秒內可「撤回」(降低誤觸風險)。

### S4 完成
- 打勾大圖示、「已經幫你送出了」。
- 下一步說明(例如要不要到場、多久有結果);需到場時顯示你們地圖的最近辦理地點與易讀路線。
- 申請編號與「查進度」入口。

### S0 掃 QR 入口
- 大按鈕「掃描 QR」。
- 錯誤訊息用白話:
  - 過期:「這個 QR 太久了,請請對方重新產生。」
  - 不是本人:「這個申請不是你的,請確認。」
  - 已使用:「這個 QR 已經用過了。」

### S5 我的協助者
- 清單:誰、什麼身分、有效到何時。
- 「新增看護/家人」(輸入或掃描對方)、「結束授權」(一鍵)。
- 看護授權預設有期限(例如 30 天)且可隨時撤銷。

## 3. 易讀設計規範(給前端)
- 一個畫面一件事;一句話只講一件事;不用縮寫、不用公文用語。
- 主要文字 ≥ 20sp,按鈕高度 ≥ 56dp,觸控間距足夠;不依賴手勢。
- 對比盡量 ≥ 7:1;狀態用「顏色 + 圖示 + 文字」三者並用。
- 返回、取消永遠看得到;任何危險操作都有確認。
- 支援系統字體放大到 200% 不破版;尊重 `prefers-reduced-motion`。
- 朗讀用瀏覽器 `speechSynthesis`(系統語音),不使用雲端 TTS。
- 設定 `lang`(zh-Hant / en / vi / id),螢幕閱讀器才會讀對。

## 4. 多語策略
- 語言:zh-Hant(預設)、en、vi、id。有餘力再加 fil、th。
- **介面固定文字:事先翻譯好存 i18n JSON**(這屬於預先產生內容,不可宣稱是即時 AI)。
- **動態內容(例如備註、地址說明)**:交給裝置端 LLM 白話化/翻譯,畫面同時顯示原文,並標示「機器翻譯,以原文為準」。
- 協助者的介面語言與長輩的介面語言**各自獨立設定**。

## 5. 給 Spring 後端的介面需求(草案,請與後端隊員對齊)
| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | /assist-requests/pending | 長輩的待確認請求(通知匣) |
| GET | /assist-requests/{id} | 取得請求內容(個資欄位已遮罩) |
| POST | /assist-requests/{id}/accept | 同意協助 |
| POST | /assist-requests/{id}/reject | 拒絕 |
| POST | /assist-requests/{id}/revise | 「有錯」,附備註退回協助者 |
| POST | /assist-requests/{id}/confirm | 長輩確認送出 |
| POST | /assist-requests/{id}/undo | 撤回(5 秒內) |
| POST | /qr/redeem | 長輩掃 QR 後兌換,**後端驗證登入者就是目標長輩** |
| GET/POST/DELETE | /delegations | 授權協助者(含看護、期限) |

AssistRequest(示意):
```
{ id, elderId, helperType, helperDisplayName, service: "elder-subsidy",
  fields: { name, idNumberMasked, birth, address, phone, ... },
  status: PENDING | ACCEPTED | REJECTED | REVISION | CONFIRMED | EXPIRED,
  expiresAt, elderLang }
```

安全要點:
- QR 只放**一次性、短效(數分鐘)代碼**,不放任何個資;兌換時後端綁定長輩帳號。
- 長輩端永遠只拿到遮罩後的身分證字號。
- 每次同意/確認都留稽核紀錄(誰、何時、做了什麼)。
- 示範資料全用假資料。

## 6. 與 TownPass 的整合點
- 微服務(網頁)嵌在 App WebView 內;已有 QR 掃描與使用者資訊的 JS Bridge handler 可用。
- 通知:避免商用推播服務;可用輪詢/WebSocket + 通知匣,或 App 既有本機通知。
- 具體做法請對照 TownPass 文件的 two-way-connection 章節。

## 7. 優先順序
1. S1 → S2 → S3 → S4 主流程(先用假資料跑通)。
2. S0 掃 QR 帶入。
3. 易讀三件事:大字、朗讀、白話文案。
4. 多語切換。
5. S5 看護授權。
6. 裝置端 AI 白話化、地圖路線。
